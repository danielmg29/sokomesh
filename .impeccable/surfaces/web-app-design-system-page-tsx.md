# /design-system — surface brief

## Scope and mode

Internal route `web/app/design-system/` (noindex). Visitor mode: **Read** — a reference people consult while building SokoMesh. Every component in the SokoMesh Feature Build Order and Field Specification v1.1 catalogue (pages 51–58), plus foundations and page templates, rendered live from the real reusable components with realistic Kenyan wholesale demo data (labelled demo).

## Audience, job, constraints

- Developers and designers building SokoMesh, and reviewers of the portfolio. Job: find the right component, see its variants and every required and commerce state at true size, see where it is used and how it maps to the contract.
- Binding: `docs/design/constitution.md` (WOVEN TRADE; MARKET/LEDGER/FLOW; motion grammar; anti-slop; required states), PRODUCT.md (KES, SellaPay STK push, no fabricated commercial evidence), CLAUDE.md placement and Adaptive Convergence rules.

## Direction contract

THESIS: The page is a component inventory: one filterable ledger of every foundation, primitive, field renderer, kernel component, block, SokoMesh extension, divergent and template, each row opening in place to its live variants and states. It refuses the category default of a docs sidebar plus one long prose page per component with floating preview boxes.

OWN-WORLD: Ink masthead with a 6px forest-green band; warm sage canvas, white bordered ledger with sunken header rows and 1px sage rules; rectangles (2px stamps, 4px controls, 8px panels); Plus Jakarta Sans headings, Inter interface text with tabular numerals, monospace only for item codes and identifiers; signal amber only for active filters, focus and reserved stock; state stamps carry drawn marks and threads carry stroke patterns, never hue alone.

STORY: The reader asks which component fits a job, what it varies and how it behaves when stock runs out or a payment goes stale. They filter by class, mode or state, open a row, inspect the live states at true size and the contract axes, and leave knowing the component's name and where it already lives.

FIRST VIEWPORT: Ink masthead (name, contract version, demo-data label, Ctrl K search). Green band. Left: H1 "Component inventory" with a one-sentence orientation; right: a bordered tally (components, field widgets, divergent). Filter bar: search input, class chips, mode chips. Ledger table, columns Code · Component · Class · Phase · Modes · States · Used in, with one row (StockAvailabilityIndicator) open showing its five states.

FORM: Inventory Ledger — position 1 of my re-roll-1 ranked list; seed key 66d74300 (re-roll 1). Signature interaction: in-place row expansion (REVEAL) with URL-backed filters and open rows, and filter REFLOW of the ledger; a 4px grid overlay toggle on any specimen.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance
