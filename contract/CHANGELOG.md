# Contract changelog

`contract/ac-contract.json` is generated by `python manage.py contract export`. Every version that changes the artefact gets an entry here in the same pull request.

Versioning: **major**: breaking (removed or renamed keys, narrowed constraints, new required fields without a default). **minor**: additive. **patch**: presentational (labels, help text, tones, widgets, messages).

## 1.0.0 — 2026-10-19

Breaking, then additive: the Advanced and Hard features, and every requirement of the specification.

- **Breaking:** `variant.stock_on_hand` is read-only. It is now the available figure from the inventory ledger (on hand less held and allocated packs, empty when a pack is not tracked); stock changes only through `inventory_balance` commands and the order flow.
- `inventory_balance` (SM-F-07, path `inventory/balances`): a pack's stock at a location, with `on_hand`, `reserved` (held for checkouts), `allocated` (to paid orders), `available`, `bin_label`; `product`, `available` and `stock_state` (in stock, running low, below one order) for reading; create to start tracking a pack; commands `receive` (input `quantity`, `note`) and `adjust` (input `quantity_change`, `reason_code`, `note`; it can never take away held or allocated packs). `inventory_movement` (path `inventory/movements`): the append-only ledger (`movement_type` receipt, reservation, release, allocation, adjustment, shipment, return; the change in available and the balance after).
- `order` (SM-F-13, SM-F-14): new status `awaiting_payment`. Checkout and approval hold each tracked pack for `ttl_minutes` (15) and the order waits for payment; a confirmed payment allocates the held packs and submits the order to its seller; an unpaid order whose holds lapse is cancelled. New command `pay` (input-only `phone`, which is not kept). The detail adds `reservations`, `hold_seconds`, `payments` (status, including `stale`, reference, masked phone, results received and duplicates), `fulfilment` and `cases`. `cancel` is open while awaiting payment; cancelling returns held or allocated stock and refunds what was paid. `dispute` now also opens a case.
- `POST payments/callbacks/<provider>`: signed provider results (`X-SokoMesh-Signature: t=…,v1=<HMAC-SHA256 of "t.body">`), applied at most once whatever their repetition. `POST payments/<id>/simulate` (sandbox only, the buyer): `outcome` approve, cancel, wrong_pin, insufficient_funds or timeout; the sandbox delivers each result twice.
- `fulfillment_task` (SM-F-16, path `fulfilment/tasks`): the pick list a confirmed order gets, with `lines` (ordered, picked, outcome, short reason, bin, on shelf); commands `start`, `record_picks` (input `picks`), `pack` (`packages`, `weight_kg`), `hand_over` (`carrier_name`, `carrier_reference`, `estimated_end_at`, `driver_name`, `vehicle_registration`, `evidence_file`, which is required). A short pick marks the order partly fulfilled; hand-over ships the picked packs out of the ledger, returns short ones to available stock, refunds their value and opens the shipment.
- `return_case` (SM-F-18, path `returns`): a buyer's claim on an order line (or the order, for a dispute) within `window_days` (14) of delivery, never more packs than are left unclaimed; commands `request_evidence`, `add_evidence` (`evidence_file`, `note`), `decide` (`decision` approved, partial, replacement or rejected; `approved_quantity`; `stock_disposition`; `decision_notes`) and `withdraw`. Deciding refunds the accepted packs and restocks them when asked.
- `api_client`, `api_token` (shown once, as `token`, in the answer that creates it; stored as a hash), `webhook_endpoint` (https on the public internet only; `secret` shown on create and `rotate_secret`) and `webhook_delivery` (SM-F-23, paths under `integrations/`). The token API under `integration/`: `products`, `inventory`, `inventory/receipts` (with `Idempotency-Key`) and `orders`, by scope, 100 requests a minute per token.
- `audit_event` (SM-F-24, path `audit-events`, administrators): the audit trail, with request and correlation ids. `GET reconciliation/checks` (each check with its count, a few examples and whether they can be traced) and `GET reconciliation/trace?q=` (an order number, a payment or reservation reference, or a correlation id). Every response carries `X-Request-ID`.
- `policies.roles`: stock, fulfilment and returns for seller roles (adjustments and decisions for managers), payment and returns for buyer roles, integrations for buyer owners and seller managers, the audit trail for administrators.
- `approval_policy.exempt_approvers` (boolean, default true, writable by buyer owners): orders placed by someone who holds one of the policy's approver roles skip it and go straight to the seller. Off, every order over the threshold waits for a second person, and checkout refuses one that nobody else could approve.
- An order's `approval` gains `placed_as` (the approver role that exempted it) and the state `not_required` for an exempt order.
- Field metadata: `default`, a new record's starting value, published for editable fields whose model default is a plain constant (yes/no, number or text; never a computed value such as the current time). Forms open on it.

## 0.6.0 — 2026-10-18

Additive (the Integrated features).

- `uploads`: what each upload accepts, `document`, `avatar` and `productImage`, as `types` (media types) and `maxBytes`, read from `AC_UPLOADS`. The server checks every file again by its own bytes.
- Field metadata: `inputOnly`. A field marked `inputOnly` is a command input (a reason, a carrier reference, a proof file); records never carry it, so clients render it in command forms only.
- `media_asset` (SM-F-05, path `catalog/media`): a product's photographs, with `scan_status`, `processing_status`, `rejection_reason`, measured `width` and `height`, writable `alt_text`, `sort_order` and `variant`, and the `remove` command. Uploads go to `POST catalog/products/<id>/media` (multipart `file`, optional `alt_text`; JPEG, PNG or WebP up to `uploads.productImage.maxBytes`). The public display copy (metadata stripped) is `GET media/<id>`, cacheable once the product is public; the original is reachable only through the signed, short-lived `original_url`. Ready photographs become the product's `primary_image` and `gallery`, each carrying `widths`, the bounded responsive widths.
- `price_rule` (SM-F-06, path `catalog/price-rules`): quantity tiers, buyer-group prices and dated promotions per variant, with `priority`, `effective_from`/`effective_until`, a derived `state` (`active`, `future`, `expired`, `off`, `conflict`) and `conflict_note`; commands `switch_off` and `switch_on`. `buyer_group_member` (path `catalog/buyer-groups`) puts a buyer organization in one of the seller's groups. `GET prices?variant=&quantity=` resolves the price the signed-in buyer pays, with its `explanation`, `tiers` and `personal`; `GET catalog/buyers` lists a seller's trading partners and group options. Product detail variants carry `tiers`; cart lines carry `price_explanation` and requote when the quantity changes.
- `cart` gains the `checkout` command (inputs `delivery_address`, `special_instructions`), which revalidates every line and places one order per seller.
- `order` (SM-F-15): new status `pending_approval`; fields `delivery_snapshot` and `quote`; filters on status, dates, totals, seller and buyer; commands `approve`, `reject` (SM-F-12), `confirm`, `start_picking`, `mark_partial`, `ship`, `mark_delivered`, `cancel` and `dispute`, with input-only `reason`, `comment`, `carrier_name`, `carrier_reference`, `estimated_start_at` and `estimated_end_at`. Detail records add `side`, `transitions` (append-only), `approval`, `shipments`, `next_actions` and `quote`. Sellers now see an order once it is submitted.
- `approval_policy` (SM-F-12, path `approval-policies`): threshold, approver roles and minimum approvals per buyer organization; `switch_off`/`switch_on`.
- `quote` (SM-F-11, path `quotes`): created from the buyer's cart lines for one seller; commands `respond` (input `offers`, `seller_notes`), `decline`, `accept` (places the order at the offered prices), `decline_offer` and `cancel`. Open quotes past `expires_at` read as `expired`.
- `shipment` (SM-F-17, path `shipments`): carrier, reference, window, status, `events`, `stale`, `delayed` and `proof_of_delivery`; commands `add_event` and `confirm_delivery` (input `proof_file`).
- `metric_definition` (SM-F-19, path `metric-definitions`), read-only, with `better` (`higher` or `lower`: which way is good news). `GET analytics` (`date_from`, `date_to`, `dimension` `day` or `product`, `metrics`) returns each metric's value, the previous period's (`null` for a metric of the present, such as stock), and a filled daily series or a top-ten breakdown; an empty average or ratio is `""`. `GET analytics/export` returns the same as CSV.
- `policies.roles`: sellers gain orders, fulfilment, quotes, price books, photographs and analytics; warehouse operators gain fulfilment and shipments; buyers gain checkout, quotes, approvals and disputes; buyer owners manage approval policies.
- Commands' `when` lists boolean values as `true` and `false`, as clients write them.
- Presentational: the order status `picking` uses the `signal` tone.

## 0.5.0 — 2026-10-17

Additive.

- `models`: the first registered resources, each declared once in `backend/core/operations/registry.py` and its app's `resources.py`: `organization`, `membership`, `address` (SM-F-01), `seller_profile`, `seller_document` (SM-F-02), `product`, `category` (SM-F-22, readable without signing in), `notification`, `notification_preference` (SM-F-21), and `account`, the signed-in person's own profile (served by `account/profile`, so it has no generated routes). Every model carries `path` (its API path under `meta.apiBase`), `lookup` (`pk`, or `slug` for products) and `public`, plus its fields, list fields, search, ordering and commands (`actions`, with `input`, `confirm`, `tone`, `icon` and `when`). Rich text appears only where the specification allows it: `seller_profile.description` and `product.description`. Records carry `_can`, the commands this person may run on that record.
- `errors`: `UNAUTHENTICATED` (401, sign in) and `UNVERIFIED` (403, confirm the email address first).
- `auth.password`: `minLength` and `help`, read from the password validators the server runs, so forms describe the server's rule.
- `policies.roles`: each role's permissions, now filled in. The web client mirrors them to show or hide controls; the API checks every request.
- `models` for the Core CRUD features: `category_contract` (SM-F-03; published versions readable without signing in; `publish` and `revise` commands; rich text `seller_guidance` and `buyer_guidance`), `catalog_product` and `variant` (SM-F-04, a seller's own catalogue; `publish`, `unpublish`, `archive`, `restore`), `cart` and `cart_line` (SM-F-10; `accept_prices`, `empty`, `remove`), `order` (SM-F-20, read-only history with the `reorder` command). The public `product` gains `brand`, `short_description`, `in_stock` (filter `eq`), `seller` filter `in` and ordering `-unit_price`; its `sku`, `pack_label` and `unit_price` are now the cheapest variant's and no longer marked required (relaxed). Policies grant the catalogue to seller roles and carts and orders to buyer roles.
- List responses (all lists): `previous`, the cursor back to the page before (null on the first page), beside `next`. The product list also returns `facets` (counts per choice, seller options, price bounds) and accepts `attr.<key>` filters for the facets of the one category it is narrowed to; their fields come from the category's contract (`category.contract.facets`), not from this file.

## 0.4.0 — 2026-10-16

Additive.

- `listQuery`: the one parameter grammar every list endpoint accepts, owned by the backend (`AC_LIST_QUERY`, validated by `backend/core/operations/listing.py`). Search is `q` (at most `maxSearchLength` characters and `maxSearchTerms` words, every word must match a declared search field). A filter is one parameter per field and operator, `<field><operatorSeparator><op>`, for the `operators` a field declares; `in` takes a `listSeparator`-separated list of at most `maxListValues` values, and a range travels as `__gte` plus `__lte`. A date-only bound on a datetime field covers the whole calendar day in `dateTimezone`. `ordering` names a field from the model's `ordering` (prefix `-` for descending), `page_size` stays within `limits.maxPageSize`, and `cursor` is the signed keyset cursor from the previous page's `next`. Responses carry `results`, `next`, `total` (counted up to `countCap`), `totalCapped` and `pageSize`. Undeclared parameters are refused with `VALIDATION`. `maxSearchLength`, `maxSearchTerms`, `maxListValues` and `countCap` are bounds: narrowing them is breaking.

## 0.3.0 — 2026-10-14

Additive.

- `richText`: the rich-text allow-list, now owned by the backend (`AC_RICH_TEXT`, sanitised on write by `backend/core/richtext.py` with nh3). `tags` maps each allowed tag to its attributes: paragraphs, `h3`/`h4`, strong, em, underline, strikethrough, inline code, lists, block quotes, rules, links (`href`), captioned images (`figure.image` > `img[src, alt]` + `figcaption`), video embeds (`figure.media` > `oembed[url]`) and simple tables. `classes` limits `figure` to `image` and `media`. `linkSchemes` (https, http, mailto), `imageSchemes` (https) and `sameOriginImages` govern URLs. `embeds` lists the video providers (YouTube, Vimeo): `url` is the canonical stored-URL pattern and `player` the privacy-enhanced player address the client builds from it. Widened from the spec p.5 list (headings, emphasis, lists, links) at the product owner's request.

## 0.2.0 — 2026-10-13

Additive.

- `locales`: the languages the backend writes to people in. `default` is `en-KE`; `supported` lists `en-KE` (English) and `sw-KE` (Kiswahili), Kenya's two official languages, with endonym labels. Source: `AC_LOCALES` in `backend/config/settings/base.py`. Clients read it for the notification language preference instead of keeping their own list.

## 0.1.0 — 2026-10-12

Initial contract.

- `meta`: `apiBase` `/api/v1/`.
- `auth`: multi-organization mode, email verification, cookie session.
- `limits`: default page size 25, max page size 100, max request 1 MiB, max upload 25 MiB, stream chunk 500, max bulk 500.
- `errors`: `NOT_FOUND`, `VALIDATION`, `FORBIDDEN`, `CONFLICT`, `DUPLICATE`, `RATE_LIMITED`, `LIMIT_EXCEEDED`, `UNAVAILABLE`, each with status, retryability and a default message.
- `policies.roles`: `marketplace_admin`, `seller_manager`, `warehouse_operator`, `buyer_owner`, `buyer_purchaser`, with no permissions yet.
- `events`, `models`: empty.
