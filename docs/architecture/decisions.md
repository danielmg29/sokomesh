# Architecture decisions

Deliberate deviations from the Adaptive Convergence v3 Web Manual and the project brief, and work that is deferred to a later slice. Add an entry whenever a rule is bent; remove it when its follow-up lands.

## Bootstrap (2026-10-12)

| # | Decision | Why | Follow-up |
|---|---|---|---|
| 1 | The layout follows manual §4.2: `contract/`, `backend/`, `web/`, `design/`, `infra/`. It does not use the brief's `apps/web` + `apps/api` + `packages/` layout. | The manual is the method being applied. `web/` matches the manual's paths, CODEOWNERS and `.gitattributes`. The root `CLAUDE.md` tree says `frontend/`, but its own placement table says `web/`. | Align the `CLAUDE.md` tree with `web/`. |
| 2 | API base is `/api/v1/`, declared once in `AC_CONTRACT["api_base"]` and exported as `meta.apiBase`. | The manual's `/api/v3` is the manual's edition, not this API's version. URL routing and clients both derive from the contract. | None |
| 3 | The contract `meta` has no `sourceCommit`. | A commit hash in the artefact changes on every commit, so the drift check could never pass. | Stamp the commit in release notes or image labels. |
| 4 | The version-bump rule is enforced by `contract export`; `contract check` verifies that the committed artefact equals a fresh export. | After an export, committed and fresh are identical, so a check-time comparison (as in the manual) cannot see what changed. | Add a CI step that classifies the diff against the base branch's artefact. |
| 5 | Built-in `django.tasks` (Django 6.0+) instead of the `django-tasks` backport. `ImmediateBackend` in dev, `DummyBackend` in CI. | `django-tasks` 0.12 moved its database backend out into `django-tasks-db`, and Django 6.1 already provides the API. | Choose a durable backend and add a `worker` compose service with the first enqueued work (SM-F-21 or SM-F-05). |
| 6 | `livekit-api` and `livekit-client` are not installed. | No SokoMesh requirement involves video or voice. | None |
| 7 | ESLint uses `eslint-plugin-boundaries` v7 `boundaries/dependencies` policies. | v7 replaced the manual's `boundaries/element-types` syntax. The manual's `ac/no-model-literals` rule does not exist as a package. | Write a local rule once the kernel exists to lint; until then the PR checklist covers it. |
| 8 | Postgres is published on host port 5433. | Port 5432 is already in use by a local Postgres install. | None |
| 9 | Tailwind's default colour palette and radius scale are cleared. | Only brand tokens can be expressed, which blocks off-brand colours and radii. | None |
| 10 | pyright runs with `django-stubs`. `reportArgumentType` is disabled only in `config/settings/*`. | django-environ types every `default=` as `NoValue`. Settings are the boundary where environment values are narrowed. | Remove the suppression if django-environ ships accurate types. |
| 11 | Generators are ESM `.mts`, split into pure render modules (`tools/contract.mts`, `tools/tokens.mts`) and small entry scripts. | Unit tests can exercise rendering without writing files. | None |

## Design system (2026-10-12)

| # | Decision | Why | Follow-up |
|---|---|---|---|
| 12 | Primitives are built directly on `radix-ui` 1.8 (the unified package), `cmdk` 1.1, `react-day-picker` 10 and `lucide-react`, not generated with shadcn/ui. | The constitution's STAMP, THREAD and UNIT language and the cleared Tailwind scales would have meant rewriting every generated file. Owning the primitives keeps one source for their look. | None |
| 13 | A `commerce` tier (`web/components/commerce/`) sits between `kernel` and `features`, enforced in `eslint.config.mjs`. | The spec classes stock, pricing, cart, checkout, order, catalogue and admin components as kernel extensions reused by many features. They know commerce concepts, so they cannot live in the model-agnostic kernel. They are not divergent either. | None |
| 14 | `/design-system` is an internal, `noindex` route that renders every catalogued component live from labelled demo fixtures (`web/features/design-system/`). | The user asked for one page that covers every component in the Build Order specification. It doubles as the visual regression surface. | Gate it behind staff auth or an environment flag before a public deployment. |
| 15 | SellaPay STK push has no callback or status endpoint in its v1 docs. Payment UI therefore shows `pending` as awaiting the buyer's approval, turns it into `stale` after a timeout, and tells the buyer not to pay again. | The contract must not claim a confirmation the provider cannot deliver. | Confirmation rule decided (#27); the delivery path for the phone result (webhook, status query or statement import) is still to be confirmed with SellaPay before SM-F-13. |
| 16 | Token additions: status tones with paired backgrounds, the `signal` role, `inverse` surfaces, 2 / 4 px stamp and control radii, motion tokens per verb, three density files. Warning is burnt orange `#9A4A12` so that it never reads as the amber signal. | These are required by the Design Constitution. Each value lives once in `design/tokens/` and is generated into CSS and TypeScript. | Dark-mode equivalents (see deferred table). |
| 17 | Contract widget coverage is tested (`web/tests/unit/registry.test.ts`): every contract widget needs a renderer, and every editable widget needs an input and a design-system row. | A field registry gap would otherwise surface only at runtime in a projected page. | None |
| 18 | The ledger's default order is "Most composed": how many page templates name a component in their block chain, derived in `catalogue.ts`. | Shows the most reused components first, and puts the signature stock indicator in the first viewport, as the surface brief requires. "Build order" restores the specification's code order. | None |
| 19 | Visible copy uses no em or en dashes, arrow glyphs or more than one middle dot per line. Empty values render the shared `Empty` ledger blank with a spoken label. Uppercase labels use one `caps` utility and letter-spacing has two tokens (`type-caps-tracking`, `type-display-tracking`). Enforced by `web/tests/unit/copy.test.ts` for dashes. | The 2026-10-13 review against the theme blend (55% Modern Mercantile, 25% Modular Trade Grid, 15% Logistics/System UI, 5% tactile) found these as template tells and as four ad hoc tracking values. | Extend the copy test to arrows and middle dots if they reappear. |
| 20 | Marketing sections lay out by container queries, not viewport breakpoints. | The same section must compose correctly at page width and inside a design-system specimen (manual 6.12). | None |
| 21 | Dark theme as `color.dark.json` with the same role names, applied by `prefers-color-scheme` unless `data-theme` overrides it; a head script applies the saved choice before paint. New roles: `chrome` (mastheads, dark in both themes), `signal-border`, `signal-hover`, `shadow`/`shadow-weight` (`brand-plate` was removed when the reversed mark landed, #22); `inverse` now means "opposite of the ground". | One component tree serves both themes through tokens; components never branch on theme. Contrast is tested in both (`web/tests/unit/contrast.test.ts`). | None |
| 22 | `logo-horizontal-reversed.svg` derived from the kit lockup for dark grounds (wordmark in brand surface, tagline in brand amber); the mark keeps its colours and sits on `brand-plate` when shown alone. | The kit has no dark-ground lockup and its wordmark is ink. | Approved by the brand owner on 2026-10-13; a reversed mark was added with the same rule, replacing the light plate. |
| 23 | New components from the spec gap review: `Pagination` (kernel, cursor links for crawlable lists), `NotificationsBlock`, `NotificationBell`, `NotificationPreferencesBlock` (SM-F-21), and templates L-18 to L-25 (list, detail, dashboard, auth, settings, seller application, reorder, notifications). | Spec p.52 phase 6 names list/detail/dashboard/auth/settings templates; SM-F-01, -02, -20 and -21 had no surface. Notification fields follow the spec exactly; no event category or locale list was invented. | Locale select landed with contract 0.2.0 (#28). |
| 24 | Colour and type audit (2026-10-13, earlier pass; colours, radii and type superseded by #25): a constant `brand` role for regions and illustration, separate from the interactive `primary`; dark neutrals warmed from OKLCH hue 160 to 140, toward the light theme's sage (about 122), with state deltas matched to light; `signal-stamp` roles so dark stamps are amber-edged rather than solid; one toggle-chip recipe (`ui/chip.tsx`, on = inverse); amber removed from warnings and successes; per-theme `display-weight` (800, 760); JetBrains Mono for identifiers; Inter `cv11`/`ss01` removed because the served font lacks them. | The audit measured dark states at half the light theme's contrast, amber used as caution, three chip on-states and platform-dependent monospace. The Jakarta and Inter pairing and both brand hexes stay, as the constitution requires. | Price slot landed (#26); photography in #25. |

## Trade infrastructure remodel (2026-10-13)

| # | Decision | Why | Follow-up |
|---|---|---|---|
| 25 | Visual remodel to the product owner's blend (Clean & Minimalist 40, Geometric 25, Professional/Corporate 20, Organic/Natural 10, Flat 5), recorded as an amendment in `docs/design/constitution.md`. Warm stone and warm graphite grounds (OKLCH hue about 90 to 105, chroma under 0.01) replace the sage and forest-night neutrals; a `well` role is the photo ground. Containers, cells, dialogs and media are square; controls and stamps keep a 2px corner. `shadow-raised` is a flat 1px edge and only overlays cast a shadow. Card lists, related records, media and category grids are joined cells (shared rules), not gapped cards. Typography is Archivo in two widths (normal for text, `type-display-width` 112.5 for headings and money figures) plus JetBrains Mono, replacing Plus Jakarta Sans and Inter. Marketing gains `TradeRibbon` (M-11), a three-tier header (terms strip, search-first row, category row) and a hero of trade terms plus a live product shelf; `CanopyEdge` is retired. | The owner judged the first build generic. References reviewed in the browser: Faire (category row, seller and product hierarchy, search first), Tanini Home (square image wells, stock tag on the well, currency and language in the header), Bélanger (white wells on warm grey, square status tags, one filter row), Joonbyrd (photography and commerce side by side; its purple and serif are not taken). Not Another Bill closed on 2026-09-30, so only its Awwwards notes (two-column product page, homepage filter) were available. | Photographs landed 2026-10-14 (approved downloads; eight Wikimedia Commons files, credits generated with the cut-outs). The superseded `web/public/images/demo/*.svg` are unreferenced and await deletion. |
| 26 | `figure` slot in the projection recipe: the first `currency` field in a model's list fields, resolved from the widget (no field name), set large in row, card, media and detail intents and removed from the meta list. | Prices were one small meta row among four; buyers compare price first. Derived from metadata, so no contract change and no model branching. | None |
| 27 | Payment confirmation rule: a SellaPay payment is confirmed only after the buyer acts on the M-Pesa prompt on their own phone and the result is a success; cancelled, failed, expired and no-result outcomes leave it unconfirmed and the order unpaid. `PaymentStatusPanel` shows the three steps (prompt sent, approval on the phone, confirmed by M-Pesa) and its copy says the payment is not confirmed in every non-success state. | Product owner decision, 2026-10-13. SellaPay's docs (checked the same day) still document no callback or status endpoint, so the UI must not imply a result it has not received. | How the phone result reaches SokoMesh and is verified (SM-F-14), with #15. |
| 28 | Contract 0.2.0 adds `locales` (default `en-KE`; `en-KE` English and `sw-KE` Kiswahili) from `AC_LOCALES` in backend settings; `NotificationPreferencesBlock` takes the notification language from it. | Kenya's two official languages. The backend owns the list so clients do not invent one; the endonym labels read correctly in either language. | Translated notification templates when the notification sender lands (SM-F-21). |

## Rich-text editor (2026-10-14)

| # | Decision | Why | Follow-up |
|---|---|---|---|
| 29 | The rich-text allow-list moves to the backend (`AC_RICH_TEXT`, sanitised on write by `core/richtext.py` with nh3 0.3.7) and is exported as the contract's `richText` (0.3.0); `web/lib/richtext.ts` mirrors it from the generated contract instead of keeping its own list. The list widens at the product owner's request: underline, strikethrough, inline code, block quotes, rules, captioned images (`figure.image`), video (`figure.media` > `oembed`, YouTube and Vimeo only) and simple tables. Video is stored as a provider reference, never an iframe; the view renders a click-to-play card and loads the privacy-enhanced player (youtube-nocookie, Vimeo `dnt=1`) only when pressed. | A validation rule kept only in client code is a defect (CLAUDE.md); a wider list makes the server's sanitiser essential. Storing references keeps scripts out of stored HTML and makes no third-party request until a reader asks. | Restrict `imageSchemes` to the media hosts when SM-F-05 lands (https images from anywhere allow hot-linking); add `frame-src` for the two player hosts if a Content-Security-Policy is set on the web app. |
| 30 | The editor is Tiptap 3.31.3 (MIT, ProseMirror) with a CKEditor 5 classic layout drawn in SokoMesh tokens, not CKEditor 5 itself. Its schema is limited to the allow-list. It loads lazily inside `RichTextInput`. | CKEditor 5 is GPL-2.0-or-later or commercial and needs a licence key; GPL would bind the whole client. Tiptap is headless, so the toolbar, forms and states use the project's own primitives, and the editor can only produce what the server keeps. | Wire `uploadImage` to the media pipeline (SM-F-05); until then images are added by address and the upload button says why it is unavailable. |

## Storefront photography and layouts (2026-10-15)

| # | Decision | Why | Follow-up |
|---|---|---|---|
| 31 | MARKET templates now follow the storefront references directly. Landing: a two-door photographic hero (`MercantileHero` `panels`, after Tanini Home), photographic category tiles (`CategoryShowcase` `photo`, after Faire), a product row of square wells, one oversized statement with a product cut-out in front of it (`TradeStatement`, M-13, after Bélanger), two photographic stories (`StorySplit`, M-12, after Joonbyrd) and a CTA with a photograph. Category page: `CategoryHero` (X-29), one filter and sort bar (`SortSelect`, K-19, labels derived from `meta.ordering` and field types) and the full width for the grid. Product page: photographs left, a sticky buying column right (after Not Another Bill). Product cells (projection `media` intent): square well, seller first, pack as one quiet line, price largest. MARKET sections are held apart by space and rise in on scroll (`scroll-reveal`, a CSS scroll timeline, off for reduced motion); operational pages keep rules. | The owner found the templates did not resemble the references. The high-end-visual-design skill's glass, pill and rounded "double-bezel" rules were not applied: they contradict the 2026-10-13 brief and the references do not use them. | None |
| 32 | Eleven Unsplash photographs (approved downloads, Unsplash Licence) prepared by `design/photography/scenes.py`: crop per slot, one warm matte grade, a baked darker lower part where white text sits and a baked light veil where dark text sits, content-hashed WebP names, blur placeholders and focal points (`focus`, applied as `object-position`). Text contrast over each hero photograph was measured on the file (at least 5.5:1 for white body text and 4.9:1 for ink body text, against the brightest or darkest 5% of pixels); below the two-column width the hero puts text under the photograph on a solid ground instead. | Text over photography must not depend on the crop; hashed names stop caches serving an old edit. Captions and alt text describe what is shown and claim no place or business. | Replace with commissioned or seller photography for a public launch. |
| 33 | The landing's mechanism sections were redrawn against the references (final review, 2026-10-15). `MarketMeshVisualization` is now one product's record on the chrome ground, its parts aligned row for row with the entries they wrote and its availability set large over its own sum; it takes the record as data (`MeshRecord`) instead of drawing a node diagram. `TradeFlowStory` is a ruled, numbered thread with the example on the well; `InventoryTrustProof` drops the segmented control for a sticky argument beside scrolling proofs; `MarketingFooter` moves to the chrome ground. Specimen plates clip with `overflow: clip`, which, unlike `hidden`, keeps sticky columns working. | The owner found the node diagram bland and off-theme; the flow and trust sections read as dashboard controls (small numbered boxes, a segmented control) on pages that otherwise follow editorial storefronts. Showing the ledger's own arithmetic makes the claim checkable rather than illustrated. | None |
| 34 | Every table that lists records searches, filters and pages live through one query engine (`web/lib/query.ts`, pure and unit-tested; `useTableQuery` holds the state). `ListBlock` tables do it by default (`query="client"`) from contract metadata: `meta.search`, fields' declared filter operators, `meta.ordering`, `meta.list.defaultPageSize`; typed commerce tables (inventory ledger, variants, top products, contract attributes, notification preferences), the chart's table view and the design-system inventory use the shared `ui` controls (`TableSearch`, `FacetChips`, `TablePager`). Page sizes are capped by `limits.maxPageSize`. The filter types now live beside the engine and the kernel re-exports them. | The owner asked for live pagination, search and filters on all tables. One engine keeps behaviour identical across tables and keeps the client from inventing filters the contract does not declare. Price tiers (two to five rows), the comparison matrix (columns are products) and rich-text tables are not record lists and were left without controls. | When list endpoints land (keyset pagination, with `SM-F-01`), server-backed lists send the same query state as allow-listed parameters and pass `query="none"`. |
